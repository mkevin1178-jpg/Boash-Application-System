# MatkulReference pending-code documentation (v1)

The only change in this diff is a comment block added to `lib/shared/matkul_reference.dart`. It documents nine course codes — GC311, GC319, IF501–IF507 — that appear in live API data but whose official names and credit counts have not yet been provided by the academic office. No new runtime entries were added; the comment is pure documentation. The existing fallback path (`sksOf` returns `null`, codes excluded from IPS/IPK, `nameOf` returns the raw code string) already handled these codes silently before this change — the comment makes that intentional gap visible and actionable. Watch for: the pending codes remain excluded from all academic calculations until filled in; if any of these codes appear in a student's KRS or nilai data today, their contributions to IPS/IPK are silently zeroed with no visible warning to the student.

**Verdict**: APPROVED

## High-level view

The `table` map in `MatkulReference` is the single source of truth for display names and credit counts consumed by both the KRS grouping layer and the IPS/IPK calculator. Codes absent from the table are shown by their raw code string and excluded from credit arithmetic — this diff documents that the nine pending codes are intentionally absent, not accidentally missed. The one open question is whether the KRS and nilai screens surface a visible warning when `sksOf == null`; the comment asserts they do, but that wiring lives outside this diff and was not re-verified.

The IPS calculator must skip `null`-SKS entries rather than treat them as zero-credit; the class-level comment states KRS and nilai screens "diberi indikator peringatan" for these codes. That contract is *likely* correct based on the orchestrator's pre-review of those screens, but it was not re-verified in this pass — the diff only touches the reference file. If the warning widget is not wired, a student with a pending-code course in their active semester will see an IPS/IPK that silently excludes those credits without explanation.
